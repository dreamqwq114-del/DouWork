# 收工台 README

## 一、作品一句话与解决的问题

**收工台：早上知道先做什么，讨论后知道谁来做，收工时知道做成了什么。**

它把三件常被各整理一遍、信息重复又容易遗漏的事串到同一份任务数据上：

1. **今日先做**：从零散待办里提取最多 3 项优先卡，并排理由；附阻塞区、待确认区与逾期提示。
2. **讨论落地**：展示讨论来源原文，从中提取行动项，人工勾选确认后才加入统一清单。
3. **收工有数**：按四段式（今日已完成 / 正在推进 / 阻塞与需要协助 / 后续计划）生成日报草稿。

解决的问题：待办、讨论记录、日报各写一遍，互相对不上；AI 提取结果没人核对就直接当成事实；"开始做了"被写成"已完成"。收工台把任务来源、状态和待确认项显式摆出来，日报只认人工确认过的状态。

## 二、文件清单与用途

| 文件 | 用途 |
|---|---|
| `index.html` | 单文件工作台，双击即可在浏览器打开，无后端、无 API key、无 CDN、无外部依赖。负责展示、编辑、状态维护、确认、复制与导出。 |
| `README.md` | 本文件：打开方法、真实 AI 使用步骤、数据边界与隐私、导入与状态规则、开发来源标注。 |
| `example-input.txt` | 配套虚构开发样例输入（待办与讨论原文），醒目标注为测试数据，非真实工作记录。 |
| `example-result.json` | 对应样例输入的结构化分析结果示例，展示"豆包侧提取后应长成什么样"，同样为虚构样例。 |
| `persona.md` | 三句话人物卡草稿，顶部已标注"待用户核实"，提交前需用户本人确认。 |
| `demo-script.md` | 三分钟以内录屏脚本，按时段列出画面与解说要点，录屏由用户本人完成。 |
| `efficiency-measurement.md` | 效率实测模板。所有计时字段留空，由用户同任务前后实测后回填，未测不填数字。 |
| `implementation-status.md` | 实现状态清单：已完成（待实测确认）/ 待验证 / 未实现，如实列出范围。 |

## 三、打开方法

- 直接**双击 `index.html`**，或把它**拖进任意现代浏览器**（Chrome / Edge 等）即可使用。
- **无需联网、无需安装、无需部署、无需登录、无需填 API 密钥**。
- 页面为纯本地静态文件，通过 `file://` 协议打开即可。

## 四、真实的 AI 使用步骤

工作台本身**不调用任何模型、不内置 AI**，页面已明确标注"不调用模型、无假 AI 按钮"。语义提取、行动项整理与日报措辞都发生在**豆包对话侧**，流程如下：

1. 在工作台点击「**复制分析材料**」，把待办 / 讨论原文复制下来。
2. 切到**豆包对话窗口**，粘贴原文（材料里请写明参考日期与时区，例如"参考日期：2026-10-25，时区：北京时间"）。
3. 由豆包真实阅读、提取并返回结构化结果，字段格式可参考 `example-result.json`（id、title、owner、due_at、status、source_id、source_quote、needs_confirmation、note 等）。
4. 回到工作台，点击「**导入分析结果**」，把豆包返回的 JSON 直接粘贴，或选择对应的 `.json` 文件导入。
5. **人工核对**：展开每条任务的来源原文，确认负责人、截止时间、状态；缺字段的项会进入"待确认区"，勾选确认后才进入统一清单。
6. 日常使用中随时改状态（待办 / 进行中 / 已完成 / 阻塞）、补备注。
7. 需要日报时：要么把当前清单状态交回豆包起草，要么直接用工作台「**收工有数**」根据已确认状态生成四段式草稿，再点「复制日报」贴走。

> 注意：不要点一个写着"AI"却只拼接固定模板的按钮就当真——本作品里 AI 只在豆包对话框里真实发生。

## 五、数据边界与隐私

- 任务数据只保存在**本机浏览器 localStorage** 中，不上传、不收集、不同步到任何服务器。
- 可用「**导出 JSON**」把数据备份成本地文件；换浏览器或清缓存会丢，需要自行重新导入备份。
- **不承诺跨设备同步**。
- `example-input.txt` 与 `example-result.json` 均为**虚构测试样例**，页面内会醒目标注"样例数据模式"，不能当成真实工作记录。
- 真实私人讨论、账号凭据、他人私聊**不应随分享 / 录屏 / 赛事提交公开**；对外分享前请脱敏或换用虚构样例。

## 六、关键规则

### 导入去重

- 按任务 **id** 去重：再次导入同一份分析结果，已有 id 的任务只更新内容，不新建重复条目。
- 出现**标题相似但 id 不同**的任务时，工作台只给出"疑似重复，是否合并"的建议，**由人工决定**，绝不静默删除旧任务。

### 四种状态语义

| 状态 | 含义 |
|---|---|
| 待办 | 还没开始做。 |
| 进行中 | 已经开始动手做了（"开始做了"= 进行中，不是已完成）。 |
| 已完成 | 用户本人确认做完；**只有已完成的项才进日报"今日已完成"段**。 |
| 阻塞 | 在等别人回复、等外部依赖；"等别人回复"= 阻塞，不自动归为完成。 |

修改状态后，日报草稿与顶部统计会随之联动；**旧日报会被标记为"已过期，需更新"**，不能继续当最新版。

### 相对时间换算前提

材料里若出现"明天""下周"等相对时间词，**只有在材料本身带有明确参考日期（和时区）时**才换算成具体日期；否则保留原文表述并放进待确认区，不凭空猜测"明天"是哪一天。
